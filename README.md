## B 站视频批量转写与文本结构化 · 2026.10

**成果**：搭建「批量下载 → 本地 GPU 转写 → 带时间戳文字稿 → 索引」流水线，完成 924 支视频，产出约 114.4 万字 / 64.2 小时语料，整理成 9 章知识库 + 16 条速查问答。

**做法**：Python + yt-dlp + faster-whisper(CUDA) + ffmpeg；断点续跑（已有稿自动跳过）；用 `initial_prompt` 控制输出，对照实验把繁体字占比从 2.7% 降到 0、专业术语识别从 0 次提到 5/5。

**难点（补充）**：
- 竖屏视频画质误判：yt-dlp 的 `height` 取长边（1280/1920），竖屏会被当成低清；改用短边 `res` 排序，横竖屏都能正确选到目标清晰度
- VAD 未开启：faster-whisper 的 `vad_filter` 默认 False，静音段会幻听；显式开启并关掉 `condition_on_previous_text` 防串台
- whisper 重复幻觉（"训练训练训练…"）影响 59 支，`fix_repeat.py` 压缩 40,505 字，复检残留 0
- 905 支连续批次全程零失败、零重试（请求间隔控制 + 登录态复用）
- 生成速度：RTX 4060 Laptop，batch_size=8，4 分钟均长视频约 14 支/分钟

## 本地加密数据库离线解密与信息密度筛选 · 2026.09–11

**成果**：自建 13 个 Python 脚本（约 4000 行）的本地提取流水线，在第三方工具下架、源码不可达的条件下实现加密数据库离线解密与消息提取；单群 76,644 条消息按信息密度筛出 683 条有效内容（压缩 84 倍），交付 HTML + JSON 双格式报告。

**做法**：XOR 解码 + 内嵌 salt 定向 PBKDF2，派生次数从 25×候选降到 1×候选（实测 25/25 命中、4 秒）；只解密必需的 6 个库而非全量 25 库（1TB+）；提取层处理 zstd 压缩、类型掩码与 sender_id 无映射表问题，用消息内容前缀反推构建发送人映射（503/503 命中）；按信息密度与同一人 2 分钟窗口聚合筛选。

**难点（补充）**：
- 排除 WAL 回放的错误方向：按页号覆盖帧导致 `database disk image is malformed`（实测回滚），确认主库持续 checkpoint、无需回放
- 修复两个缺陷：空缓存文件被当成有效缓存导致永久跳过密钥扫描；输出目录不存在时首次运行必崩
- 数据缺口诊断：建立主库体积跳变（MB 级 = 手机迁移正在合并）与逐日消息量双判据，避免在中途窗口误判"没落地"
- 读进程内存用 `OpenProcess + PROCESS_VM_READ`，普通权限即可，无需管理员

**难点（补充）**：

- 「能拿 IP + 打不开网页 + 上网灯灭 + DNS 拒绝」三连应优先怀疑拨号认证

## Node 同步子进程限制绕过 · 2026.09

**成果**：绕过托管 Node 运行时屏蔽同步子进程的限制，让依赖 spawnSync 的第三方 CLI 在本机可用。

**做法**：在 require 前 monkey-patch child_process 同步 API，用 make-synchronous（worker_threads + Atomics）把异步 spawn/exec 包成同步。

**难点（补充）**：worker 内 require 未定义，须改动态 import('child_process')；关沙箱、起后台进程都无效，确认是运行时对同步等待的限制而非权限问题。
